# MLX周辺機器記事化の現行ルール

最終更新: 2026-08-13

## 1. この文書の目的

この文書は、Blog VercelからMLXで周辺機器記事を作るときの現行処理と、記事化を停止させるフィルターを一覧化するものである。

現在の実装は、MLXに親記事全体を書き直させない。MLXが生成するのは、冒頭へ追加する一文、カテゴリ共通説明文、おすすめ商品ブロックの調整結果だけである。タイトル、H2見出し、親記事との合成、OneDrive保存はPythonの決定的処理で行う。

## 2. 記事化の全体フロー

1. Blog Vercelの記事一覧で親記事を右クリックする。
2. 「周辺機器記事作成」から対象カテゴリとMLXを選ぶ。
3. Blog Vercelが `周辺機器DB` のカテゴリ定義と `affiliate_links.txt` の対応セクションを確認する。
4. 親記事ごと、カテゴリごとにOneDriveジョブJSONを作る。
5. `周辺機器DB_LLM` に `記事化` 行を登録する。
6. `blogvercel-mlx://run`からTerminalと `/Users/user/Library/CloudStorage/OneDrive-個人用/開発/MLX/start_accessories_worker.command` を起動する。
7. MLXワーカーがジョブをロックし、親記事、プロンプト、対象商品群をOneDriveから読む。
8. MLXサーバーのGemma E4Bに限定JSONの生成を依頼する。
9. ジョブJSONに固定された1～3回の範囲でMLX応答を生成・検査する。既定値は1回で、複数回の場合はそれまでの検査エラーを次回へ渡す。
10. 合格応答、または選択回数すべてが不合格だった場合の安全な原文フォールバックを親記事へ組み込む。
11. 完成Markdownを検査する。
12. OneDriveの `周辺機器/{YYYYMMDD_HHMM_親記事タイトル先頭20文字}/` へ保存する。
13. 管理用JSONを記事ルート外に保存する。
14. `周辺機器DB_LLM` を `完了` または `失敗` へ更新する。

## 3. MLXが受け取る情報

MLXへは次の情報を渡す。

- 親製品名
- 対象周辺機器名
- `affiliate_links.txt` の対応セクション直下にあるカテゴリ共通説明文
- 対応セクション内のすべての `▼` 商品ブロック
- OneDriveに保存された実行時プロンプト

`extract_generation_evidence()` は親記事の結論と仕様根拠も抽出しているが、現行の `build_prompt_input()` はその `evidence` をMLX入力文に含めていない。したがって、現行MLXが実際に見ているのは、親製品名、周辺機器名、共通説明文、商品ブロックである。

## 4. MLXが生成する範囲

MLXは次の3キーを持つJSONだけを返す。

```json
{
  "intro_sentence": "冒頭に追加する一文",
  "adapted_section_intro": "共通説明文の調整結果",
  "products": [
    {
      "index": 1,
      "adapted_text": "商品1の調整済みブロック"
    }
  ]
}
```

MLXに記事全文、H1、H2、リンクまとめ、Frontmatter、管理情報を生成させない。

## 5. プロンプト上の生成ルール

### 5.1 冒頭文

- 親製品名を含める。
- 周辺機器名を含める。
- その周辺機器のおすすめ商品を紹介する旨の短い一文にする。

### 5.2 カテゴリ共通説明文

- 原文を優先する。
- 自然にできる場合だけ、`おすすめ` を含む行の主語を親製品名に変える。
- 不自然な場合は原文をそのまま返す。
- 原文の各行、空行、箇条書き、判断基準、利用シーン、数値、単位、順番は削除しない。
- 原文を保った補足行の追加は許可するが、行数を減らさない。
- HTMLの `<br>` は使わず、Markdownの通常改行を維持する。
- 原文が空なら空文字を返す。

### 5.3 商品ブロック

- `▼商品名` 行を変えない。
- URL、型番、容量、出力、価格、数値、商品順を変えない。
- 原文を優先する。
- 自然にできる場合だけ、親製品名を主語にする。
- 不自然な場合は原文をそのまま返す。
- 元の商品ブロックに紹介文がない場合だけ、おすすめ理由を一文追加できる。
- 入力にない仕様、互換性、価格、評価、用途を創作しない。

### 5.4 出力禁止項目

- 記事全文
- タイトルと見出し
- おすすめ商品のリンクまとめ
- FrontmatterとYAML
- 作業手順
- 内部思考
- 管理用メタ情報
- Amazonアソシエイト免責文
- AI整形・編集の注記

## 6. MLX API側の出力制御

`/Users/user/Library/CloudStorage/OneDrive-個人用/開発/Gemma4_AMZN_Blog/MLX/accessories_engine.py` は次の制御を行う。

- モデルは原則 `mlx-community/gemma-4-e4b-it-8bit`。
- `temperature=0.25`。
- `top_p=0.9`。
- `max_tokens=16384`。
- ストリーミングは使用しない。
- Thinkingを無効にする。
- ツール呼び出しを無効にする。
- vMLXの厳密JSON Schemaを使い、3キーと商品配列の型を制御する。
- APIがHTTPエラー、`choices`なし、空応答の場合は停止する。

## 7. LLM応答に対するフィルター

### 7.1 JSON構造

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| 空応答 | 返答が空 | API異常の検出 | 維持 |
| JSON解析 | JSONオブジェクトを回収できない | 本文へ内部出力を混ぜない | 維持 |
| ルート型 | JSONのルートがdictでない | 処理契約の維持 | 維持 |
| キー完全一致 | 3キー以外がある、または不足 | 不要なメタ情報の混入防止 | 維持候補。余分な無害キーまで停止させる点は緩和可能 |
| 商品配列数 | 入力商品数と違う | 商品欠落の防止 | 維持 |
| 商品番号 | `index` が1からの順番と違う | 商品順の維持 | 維持 |

JSON解析は、JSON本体、Markdownコードフェンス内のJSON、前後に説明が付いたJSONの順で回収を試みる。回収できない場合は解析エラーの行と列を表示する。

### 7.2 冒頭文

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| 空文字 | 冒頭文が空 | 案内文の欠落防止 | 維持 |
| 親製品名 | 冒頭文に親製品名がない | 対象記事との関連の明示 | 緩和候補。表記揺れで失敗しやすい |
| 周辺機器名 | 冒頭文にカテゴリ名がない | 追加内容の明示 | 緩和候補。充電器とアダプター等の表記揺れで失敗しやすい |
| URL・改行 | URL、改行、`<think>`、`job_id` がある | 一文化と内部情報混入防止 | 維持 |

### 7.3 カテゴリ共通説明文

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| 元文なし | 元文が空なのに文章を追加 | 創作防止 | 維持 |
| 調整文の空 | 元文があるのに空文字 | 説明文欠落の防止 | 維持 |
| 行数減少 | 原文より調整文の行数または空行数が減る | 原文構造と改行の維持 | 維持。原文行を順番どおり残した追加行は許可する |
| 原文行の欠落・大幅改変 | 原文の非空行が順番どおり残っていない | 原文の削除と全面書換え防止 | 維持。おすすめ行の主語だけを調整した変更は許可する |
| HTML改行 | リテラルの `<br>` がある | 保存Markdownとnote本文へのHTML混入防止 | 維持。画面表示だけ通常改行を改行表示する |
| URL完全一致 | URLが追加、削除、変更された | 収益リンクの保護 | 維持 |
| 既存英数字の欠落 | 独自抽出した英数字トークンが削除された | 仕様欠落防止 | 緩和候補。抽出対象が広く、表記整形で誤判定する可能性がある |
| 新規英数字の追加 | 原文と親製品名にない英数字トークンが追加された | 仕様の創作防止 | 緩和候補。安全な表記変更でも失敗する可能性がある |

共通説明文は、親製品名を入れず原文のまま返しても現在は合格する。ただし、一文でも変更すると上記の厳しい条件が適用される。

### 7.4 商品ブロック

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| 商品名行 | `▼商品名` で始まらない | 商品名の保護 | 維持 |
| URL完全一致 | URLの配列が原文と違う | 収益リンクの保護 | 維持 |
| 新規数値・英数字 | 原文と親製品名にない抽出トークンが追加された | 仕様の創作防止 | 緩和候補。日本語の内容創作は捕捉せず、一方で無害な英数字に反応する |
| 行数減少 | 原文より調整文の行数または空行数が減る | 商品文と改行の保護 | 維持。原文行を順番どおり残した追加行は許可する |
| 原文行の欠落・大幅改変 | 商品名・URLを含む原文行が順番どおり残っていない | 原文削除と全面書換え防止 | 維持。親製品を主語にする最小変更は許可する |
| HTML改行 | リテラルの `<br>` がある | 保存Markdownとnote本文へのHTML混入防止 | 維持 |
| 禁止文言 | `<think>`、`job_id`、免責文、AI注記、リンクまとめがある | 内部情報と不要文の混入防止 | 維持 |

商品ブロックに親製品名が含まれることは、2026-08-13の修正で必須条件から外れた。原文のままでも合格する。

## 8. 記事組立ルール

MLX応答が合格すると、Pythonが次の範囲だけを変更する。

- H1を `親製品名 周辺機器名おすすめまとめ` 形式へ変換する。
- すべてのH2を `親製品名 周辺機器名おすすめ: 元見出しの題意` 形式へ変換する。
- H1の直後へMLXが返した冒頭文を追加する。
- 親記事の最初の `▼` から次の `▼` またはH2直前までを、最初の商品ブロックとして維持する。
- 最初の商品ブロック直後へ `## 親製品名 周辺機器名おすすめまとめ：結論` を追加する。
- 専用結論見出し直下へ、共通説明文と全商品ブロックを順番どおり追加する。
- 親記事に `▼` がない場合は、最初のH2直前へ専用結論を追加する。
- H3以下と既存本文は変更しない。

## 9. 完成Markdownに対するフィルター

### 9.1 公開本文の安全検査

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| UTF-8 BOM | 先頭にBOMがある | 文字・記事解析の安定 | 維持 |
| 先頭H1 | 最初の空白でない行がH1でない | 余計なメタ情報の防止 | 維持 |
| H1数 | H1が1件でない | 記事構造の保護 | 維持 |
| YAML Frontmatter | 先頭に `---` がある | 公開本文へのメタ情報混入防止 | 維持 |
| JSON包み | 記事全体が `{` または `[` で始まる | LLM応答の誤保存防止 | 維持 |
| コードフェンス | 記事全体がコードフェンスで始まる | LLM応答の誤保存防止 | 維持 |
| 内部思考 | `<think>` 等がある | 内部出力の混入防止 | 維持 |
| 作業説明 | `以下のように修正`、`作業手順`、`出力フォーマット` がある | 作業メモの混入防止 | 緩和候補。親記事に元から同じ表現があると誤検出する |
| 管理キー | `job_id`、`batch_id`、`parent_id` 等がある | 管理情報の混入防止 | 維持 |
| HTML管理コメント | 管理用語を含むHTMLコメントがある | 隠しメタ情報の防止 | 維持 |
| リンクまとめ | `おすすめ商品のリンクまとめ` がある | 不要な重複リンクの防止 | 維持 |

### 9.2 商品掲載検査

| 検査 | 不合格条件 | 目的 | 評価 |
|---|---|---|---|
| 商品ブロック数 | 調整済みブロック数と元商品数が違う | 商品欠落防止 | 維持 |
| 共通説明文の存在 | 元文があるのに完成記事にない | 説明文欠落防止 | 維持 |
| 共通説明文の一意性 | 同じ文章が2回以上ある | 重複防止 | 維持 |
| 商品ブロックの完全一致 | 調整済み文章が完成記事内に見つからない | 組立欠落防止 | 維持候補。改行正規化後の完全一致なので少しの整形に弱い |
| 商品ブロックの一意性 | 同じブロックが2回以上ある | 重複防止 | 維持 |
| 掲載順 | 共通説明文と商品ブロックの位置が原順でない | 一括掲載順の保護 | 維持 |
| 必須URL | 対象商品のURLが記事にない | 収益リンク欠落の防止 | 維持 |

## 10. MLXの生成再試行

- LLM応答の生成と検査は、画面右上の歯車で選択した1～3回行う。既定値は1回である。
- 各回で同じプロンプトと入力商品群を使う。
- 2回目以降へ、それまでに発生した全検査エラーを渡す。
- 選択回数すべてが不合格なら不合格応答は使わず、親製品名から始まる決定的な冒頭文、原文のカテゴリ共通説明文、原文の商品ブロックで安全な記事を保存する。
- 安全な原文フォールバックで保存したジョブは `完了` とし、Blog Vercelへ `警告あり・出力済み` と全試行エラーを表示する。

親記事取得、OneDrive保存、ジョブ破損など、記事本文を安全に作れない入出力障害はフォールバック対象外であり、従来どおり `失敗` とする。

## 11. ジョブと運用上のフィルター

これらは記事文章の品質フィルターではなく、二重実行、破損ジョブ、誤ったエンジン実行を防ぐための運用検査である。

- ジョブSchemaが対応バージョンであること。
- エンジンがMLXまたはGeminiであること。
- MLXワーカーはMLXジョブだけを処理すること。
- ジョブ状態が許可値であること。
- 親記事IDとタイトルがあること。
- カテゴリID、表示名、アフィリエイトセクション、テンプレートがあること。
- `周辺機器DB` 行スナップショットのSHA-256が一致すること。
- プロンプト本文のSHA-256が一致すること。
- 完了済みジョブを再生成しないこと。
- 他ワーカーが有効なleaseで処理中のジョブを取得しないこと。
- OneDrive更新時にETagが一致すること。
- OneDriveから読むテキストがUTF-8であること。
- `周辺機器DB_LLM` の対応ジョブIDが1行だけであること。

これらは原則として維持する。緩和すると記事の二重生成、古いプロンプトの混入、スプレッドシートとOneDriveの不整合が起こり得る。

## 12. フィルターが多いと感じる主な原因

現在は一つの生成結果に対し、次の重複した保護を行っている。

1. プロンプトで変更を禁止する。
2. vMLXのJSON Schemaで出力構造を制限する。
3. PythonでJSON構造を再検査する。
4. Pythonで共通説明文と商品文の内容を検査する。
5. 記事組立後に、同じ文章の存在、回数、順番を再検査する。
6. 公開Markdownのメタ情報混入を検査する。

プロンプトとJSON SchemaだけではLLMの誤出力を完全に防げないため、保存前検査自体は必要である。ただし、文字列類似度の一律判定と行数完全一致は、保護対象と誤判定の釣り合いが悪い。このため現行実装では全体類似度60%・行ごとの類似度65%を廃止し、原文行の順序、URL、商品名、数値仕様、行数減少を個別に検査する。

## 13. フィルター整理結果

2026-08-13の改修で、誤停止しやすかった類似度と完全行数の条件を整理した。次のうち「反映済み」は現行コードの動作、「継続検討」は今後さらに簡素化できる候補である。

### 13.1 必ず維持する

- JSONが読めること。
- 商品数と商品順。
- `▼商品名` 行。
- Amazon等のURL完全一致。
- Frontmatter、YAML、JSON包み、内部思考、管理情報の非混入。
- リンクまとめと免責文の非生成。
- H1が先頭に1件だけあること。
- 共通説明文と各商品が1回ずつ、元順で掲載されること。
- ジョブロック、ETag、SHA-256、完了済みの再生成防止。

### 13.2 反映済みの緩和

- 冒頭文は親製品名から必ず開始し、周辺機器を探しているか問いかけ、おすすめ商品と商品情報をあわせて紹介する。
- 共通説明文と商品ブロックの行数完全一致をやめ、行数減少だけを不合格にする。
- 原文行を順番どおり保持した補足行の追加を許可する。
- 共通説明文と商品ブロックの全体類似度60%・行ごとの類似度65%を削除する。
- 2回目以降へ、それまでの全検査エラーを渡す。
- 選択回数すべてが不合格でも、安全な原文フォールバック記事を警告付きで保存する。

### 13.3 継続して検討する

- 冒頭文のカテゴリ名の完全一致。
- 原文行の主語変更に対する英数字トークン検査。
- 完成記事内の調整済みブロック文字列完全一致。
- 完成記事全体を対象にした「作業説明」の固定文言検出。

## 14. 推奨する最小フィルター構成

安全性と記事化成功率の両方を重視し、現行実装は次の構成を基準とする。

1. JSON Schemaで出力構造を保護する。
2. 商品数、番号、順番を保護する。
3. `▼商品名` とURLを完全一致で保護する。
4. 容量、出力、価格等の重要数値だけを構造化して保護する。
5. 禁止メタ情報と内部思考の混入を防ぐ。
6. 共通説明文と商品ブロックの欠落、重複、順番違反を防ぐ。
7. 全体類似度、完全行数、親製品名の完全一致は合否判定に使わない。
8. 生成に合格しない場合も原文から安全に組み立て、警告と全試行エラーを残して記事化を続行する。
